# Tutor audit — source, existing evidence and no-cost checks

Audited after Jordan's merge498bfa974658f6a1ad4e68a5cd0a5e509201ac27. Scope: existing Riley / BeastEducation Tutor, not a new agent or new assessment framework. No model/API inference, real learner records, subscription, customer changes or claim of live competency. Source baseline is the exact Jordan merge, whose src tree matches tested candidate02f4a478.

## Existing path and protections

`src/app/api/learning/ai/route.ts` authenticates with getUser and professional entitlement, validates request/image, obtains per-member request lease, runs input safety, loads server-owner-scoped profile/latest Tutor conversation, bounds/sanitizes history, invokes the learning provider, then performs deterministic and semantic output safety. Caller-provided learner identity, mastery and history are not trusted as canonical profile; server context uses a neutral learner label and age band. Raw images are not placed in persisted Tutor history. Existing workspace uses owner-scoped conversation persistence. No arbitrary record/grade/submission tools were found in this path.

`src/lib/learning/openai.ts` uses the existing OpenAI Chat Completions adapter and `OPENAI_LEARNING_MODEL` (source fallback gpt-4.1-mini; hosted effective value NOT inspected). Text turn has generation plus two safety calls. Image turn adds worksheet transcription before teaching: normally4 provider requests, not one. Worksheet text is untrusted/sanitized. Strict teaching envelope and safety contract are validated; this is structural protection, not proof the explanation is right.

Existing21 relevant local checks passed: be301Tutor, tutorConversationRegression, tutorContextAwareness and tutorConversationScroll. They cover identity/navigation/age boundaries, owner-derived limited context, image type/3MB bound, policy/orchestration/history and scrolling. Existing full application suite also passed before Jordan release. No new competency grades assigned; these checks cannot prove arithmetic, visual transcription, diagnosis of the first learner error or teaching quality.

## Prioritized demonstrated gaps

1. **Bound cancellation and provider work before further Tutor changes.** `providerMessages` and `callOpenAILearningSpecialist` call fetch directly without explicit AbortSignal/timeout or output-token bounds. The route's request.signal reaches the classifiers but not these generation/transcription calls; there is no whole-route deadline in this file. A disconnected learner or slow provider can leave work running and the in-memory lease held until fetch returns. The shared Jordan evaluation hook is not a spending guard for these direct calls. This audit does not assert a new production incident or authorize paid tests. Smallest correction: pass one caller/deadline signal through existing adapter, explicit model-compatible output ceilings and no retry; local mocked abort/finish cases.
2. **Reject incomplete provider responses explicitly.** Adapter consumes message.content without checking choices.finish_reason or retaining token usage. Nonempty truncated text can proceed to schema parsing/teaching; output classifier is not a reliable completion meter. Preserve terminal reason, refuse incomplete work, and retain safe usage telemetry without worksheet text. No need for a new service or framework.
3. **Telemetry overstates completed delivery.** Route records completed immediately after generation status ready, before output safety and return. Subsequent safety failure/fallback can therefore count as completion. Move delivered/failed measurement to the actual validated outcome; distinguish protected fallback from useful teaching.
4. **Evidence limits on homework review.** Final semantic verifier receives member text and candidate prose but not the actual worksheet/transcription or complete teaching history. It cannot independently establish transcription accuracy or full homework support from those fields. Existing safety-contract enforcement is valuable but cannot be labeled independent factual grading. Retain this limitation; any future engineering should pass only necessary private evidence to the existing verifier, not public search.

No confirmed cross-tenant disclosure was found in inspected code. This is not a live RLS/auth penetration test: hosted sessions, deployed settings, actual image handling and rendered learner workflow were not exercised. The 3MB limit checks data-URL/MIME/decoded length, not full image decoding; do not claim image-file semantic validation.

## Audit outcome

Existing functional Tutor foundation is present. Operational cancellation/completion accounting gaps are concrete and should be corrected before declaring a finished reliability upgrade. No proof of live teaching competence is available from this audit. Recommended next engineering pass is narrow adapter/telemetry correction with existing tests only—no model migration, new vendor, paid probe or new framework. No Tutor application code changed under this audit.
