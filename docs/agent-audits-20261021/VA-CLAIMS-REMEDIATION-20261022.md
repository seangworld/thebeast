The prior VA audit remains unchanged. VA Claims Aide remains Taylor's veterans specialization; no new agent, model, service, entitlement, filing, VA-account or representation capability.

## Complete flow and concrete corrections

1. **Selection/ownership.** The authenticated/entitled runtime already scopes the conversation and reads by owner. Selected claim lookup now also validates the exact returned ID, owner, saved revision and valid claim/type/status before generation. Selected original loading checks exact unique requested IDs, owner, Health category and nonarchived status before download. Existing authenticated Storage, file signatures and combined10MB maximum remain. Actual downloaded bytes receive a private SHA256 with metadata updated-at: this proves snapshot identity, not source authenticity or clinical/VA truth. No storage path, raw file or member identifiers enter telemetry.
2. **Switching issues.** Previously a new claim was appended to all prior conversation state/memory and selected documents stayed checked. New VA turn metadata binds claim ID/revision/update and original-document ID/digest/update to the saved assistant message and its user message ID. Only same-claim/revision tagged history is available as context; unknown legacy turns and other claims are excluded. All unscoped global memory is omitted in veterans mode. Cached state resets when the selected issue/revision/originals change. Prior same-claim history retains its old document stamps and is never presented as a fresh reading of an unselected original. General VA assistance is scoped to its selected original set. Returning to ordinary Health excludes tagged VA turns and resets VA continuity; stored conversation remains visible and is not erased.
3. **UI prevents accidental carryover.** Claim/mode changes clear selected originals, with an explicit reselect notice. An unsent question must be cleared or sent before switching issues/mode, rather than silently applying its facts elsewhere or deleting the question. The current maximum of two originals is preserved.
4. **Member account versus evidence.** The selected claim is a separate explicitly member-entered/unverified input; it is no longer placed among canonical clinical records. Saved status/tracker/draft never becomes VA or clinical verification. `filingEnabled:false` remains explicit. Background health source labels are unverified and relevance must be established, not borrowed from another claim. New claim context goes through the existing instruction-injection quarantine before planning/synthesis/checking. Existing no-diagnosis/no-nexus/no-guarantee and scoped secondary-theory safeguards remain.
5. **Explanation/draft validation.** The final existing private safety check now receives selected claim/member context and the already-selected originals themselves. It previously had only member question and candidate prose, so could not compare invented draft facts to the original. No additional provider request or download is added; the original bytes remain confined to the existing private provider with store:false and no tools. VA check output is bounded at2,000tokens; the existing45-second checker/caller deadline remains. Incomplete checks fail closed. Instructions require each draft factual clause to follow explicit member account/readable evidence, preserve conflicts/laterality, disclose missing/unreadable pages and leave unsupported diagnoses, continuous symptoms, dates, causal theories and conclusions unknown. Assistant drafts, cached state and examples are not facts. This wiring does NOT prove the model judges those sources correctly.
6. **Rejected-plan continuity.** A final local regression demonstrated that replacing rejected prose did not replace its generated continuity state. VA rejection or scope withholding now keeps prior scoped state and removes generated proposals/action hints. Unsupported draft facts cannot be promoted to the next turn merely because the prose was withheld. This is a reproduced mechanics fix, not proof the classifier recognizes every unsupported statement.
7. **Saved result.** The organizer already kept unsaved edits, used owner/revision compare-and-set and did not overwrite an existing statement. It now verifies returned content, not just ID/revision; an unexpected changed draft cannot be acknowledged as saved. The VA AI conversation path now confirms both inserted message identities/ownership, recounts owner/conversation messages (including earlier interrupted saves), and confirms a compare-and-set summary update affected the expected row/count. A zero-row/conflicting/error result cannot emit completed status. Save errors explicitly warn that some messages may already have saved and to review before retrying. Selected-source failures use a fixed nonsensitive unavailable message; they do not leak another owner's existence or invent unreadable contents. No automatic retry. Messages/summary remain separate writes, not an atomic transaction; no schema migration is introduced.

The VA specialization's **target is core L3 contextual, member-directed preparation**: use the correct selected issue and originals; explain attributable findings; preserve uncertainty/conflicts; draft only supplied facts; guide correction; accurately report saves; retain owner authority. It does not require or authorize adjudication, autonomous filing, representation or account access. Taylor's existing scoped Health L3 / target L4 are unchanged and do not certify VA.
