# Central staff dossier maintenance and release checklist

Canonical owner-only home: `/dashboard/operations/staff`. BeastAdmin and other products link here; profiles remain their identity/duties sources and evidence stays attributable to its original record. Version-controlled reviews and external inventory are the dossier source, not a second database. Telemetry is deliberately separate and unavailable telemetry cannot erase a dossier.

Every staff change must review and update the corresponding profile/review/history before completion. Record date, responsible executor/reviewer, reason, version or PR, live/local/replay evidence, criterion results, limitations and deferred work. After deployment/rollback update release history and synchronization status again. Never raise a numeric competency level just because code was released or tests passed. No new paid assessment cycle or approval request.

The build's offline `check:staff-dossiers` gate checks source fingerprints against an appended maintenance receipt. It covers shared runtime/prompts/config, learner adapter, member safety, Atlas, development profiles/capability projection, marketing persona and VA organizer. Add watch roots when adding agent implementations. `--base origin/main` also rejects rewriting history or changed source without an appended receipt. It is a maintenance check, not proof of semantic honesty; reviewers must verify that the affected dossier content actually reflects the change. New methods of changing agent behavior require adding their paths to the gate.

Cross-repository work: use the canonical staff IDs/aliases in the HQ register, and include a same-work HQ patch/PR alongside external instructions/changes. If synchronization is not yet deployed, label it pending. Do not duplicate dossier stores in other repositories. Import only reviewed public/source metadata, never credentials, customer records or raw private prompts. External snapshots show repository commit/date and are not live status feeds.

Deferred improvement cost fields must state known assumptions/date/scope; distinguish engineering effort, inference/tool estimates, prerequisite credit/service fees and recurring operation. Unknown remains unknown. Historical estimates are not current quotes, spending approval or invoice charges. All agent testing remains no additional spending; revisit deferred spending only if Sean independently changes that policy.

Completion: source/history gate; meaningful dossier/owner-access/filter tests; full local tests; TypeScript/lint; security-gated build; actual desktop/mobile roster checks; exact preview/main/release identity; non-inference production auth gates; confirmed dossier release-history update. No AI message is required or authorized by these checks.
