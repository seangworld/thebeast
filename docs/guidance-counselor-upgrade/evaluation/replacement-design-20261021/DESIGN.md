# Revised Jordan research replacement design — before implementation

**Recommendation:** an application-controlled research pipeline using a **licensed, per-request general web-search API for discovery**, followed by **independent bounded public-page retrieval** and **tool-free evidence extraction**. Retain the successful private brief, separate privacy review, private contextual synthesis and final safety screen. Keep the existing models unless a separately justified decision changes them.

This supersedes the catalog-only discovery suggestion in `../contract-review-20261021/REPORT.md`. That earlier suggestion would narrow Jordan's role. Ordinary research must accept an unfamiliar school, program, credential issuer or public authority by name; a user-supplied URL is optional, never the ordinary prerequisite. A fixed source catalog is only a reusable identity-evidence cache and discovery hint. An unknown target always enters general discovery, not automatic refusal.

This is design only. No replacement runtime, service activation, subscriptions, new credentials, paid calls, migrations, merge or deployment under this task. No new spending approval is requested here.

## 1. Discovery and retrieval are separate services

**Discovery finds candidate URLs; it does not establish their truth.** The application sends approved public search terms to a general search index. Results identify candidate organizations, official sites, relevant pages and corroborating public directories. Search rank, snippets, plausible domains and .edu suffixes do not establish official identity or current requirements.

**Retrieval downloads selected pages directly from their public origins.** The application retains exact fetched contents and their origin metadata, under applicable permissions and retention rules. Requirements, fees, deadlines and credential rules must trace to these retrieved documents. No search snippet or search-provider-generated answer becomes a verified factual finding.

No OpenAI-hosted web tool, hidden agentic search loop, Answers endpoint, LLM Context endpoint, SERP scraping, assumed free search API, automated browser-account search or model-guessed URL is substituted for the discovery service.

## 2. End-to-end sequence

1. **Input safety, private brief, separate privacy:** preserve existing Low input check, Minimal extraction and Medium privacy stages, runtime relevance/uniqueness validation, FSA/FAFSA authority handling and clarification rules. Actual original message and genuine follow-up state stay private. Only the reviewed public brief can cross into search. This prevents sending learner name, home address, phone, finances, health or private capacity. Empty/ambiguous target triggers a name/location/program question, not a demand for a URL.
2. **Bounded general discovery:** derive transparent query templates from the brief. For each of at most two targets, use one identity query and one requirements/program query. Four HTTP search attempts maximum, including failures; no automatic retry, pagination, batch hidden subqueries or paid query-generation model. Search the open index for unknown targets; domain filters can refine a verified target but must not restrict initial discovery to a catalog. Return up to ten candidate URLs/request with clear provider/request/query provenance. In multi-target jobs allocate both targets a discovery opportunity before optional refinement. Each follow-up uses the corrected year/version and genuine prior history, not cached old facts.
3. **Candidate retrieval and identity resolution:** fetch the candidate organization's about/contact/program pages and relevant directory/regulator/issuer cross-references. Use matching legal/public name, requested location/campus, public institutional relationships and first-party program/credential ownership. Preserve which document/quote supports each identity link. A domain suffix, TLS, same-host self-assertion or catalog entry alone is insufficient. Public authorities need their public statutory/government identity, not an invented school; credential issuers need exact credential/version ownership. Discover and allow new hosts dynamically after security checks; do not require owner registration for each new school. Conflicting identities remain uncertain; ask for distinguishing public information when needed. This is evidence-based corroboration, not independent institutional certification.
4. **Independent bounded retrieval for requested facts:** select relevant catalog, admissions, fee, aid or issuer pages and at most a bounded set of on-page links from already retrieved content. A candidate may be fetched while still unverified, but its facts cannot be promoted to official evidence until identity is corroborated. No guessed links are accepted as consulted evidence. PDFs need a bounded local text extractor, not another paid research service. Dynamic-only/challenged/scanned sources remain a disclosed limitation.
5. **Tool-free evidence extraction:** one capped model request sees the public brief and retained source texts, never private member records. Produce structured identity assertions and findings with document ID, exact quote, character/page location, target/program/campus, intake/version, effective date, fee scope/residency and uncertainty. Runtime validates quote existence in retained text, valid document hashes, target scope and explicit applicability fields. An exact quote proves that text was retrieved, not that a model's interpretation is correct. Unsupported/missing facts and conflicts remain explicit; no silent correction/truncation of invalid model output.
6. **Contextual synthesis:** preserve the existing private stage. Feed the actual learner context plus accepted findings and citations. Respect current planning capacity without silently updating persistent profile records. Distinguish general requirements from personal eligibility, published rates from projections, and payment dates from application deadlines. No submissions, records changes or claimed completed actions in research synthesis.
7. **Final safety/grounding and delivery:** retain citation allowlist plus claim-specific semantic review. Every factual claim cites an accepted finding/document; identity evidence only supports identity. Final verifier receives the same retained evidence, not only a URL list. Unknown usage, incomplete output or rejected checks halt without presenting a researched success. Persist the result and settled accounting before observer delivery, retaining undelivered diagnostics separately. No lower-count or post-hoc billing reinterpretation.

## 3. Source audit package and privacy

A future run records a stable evidence graph:

- Private context/history and approved public brief, under existing owner-only evaluation access.
- Discovery query, provider/endpoint/pricing version, request identifier/time/status, candidate result provenance and request-cost reservation. Retaining actual search results or snippets requires explicit provider rights; absent those rights this provider is ineligible for the auditable design. Do not silently discard provenance or assume it can be stored because the service returned it.
- Independently fetched original/effective URLs, redirect chain, DNS/public-address checks, status, content type/encoding, retrieval timestamp, source-published/effective date when present, exact body bytes/text, parser version, truncation/coverage flags and SHA256. Page contents have their own applicable access/retention/copyright constraints; search licensing does not grant unrestricted page redistribution.
- Identity-support relationships, extracted claims and verbatim quotes/locations, rejected evidence and reasons, actual model requests/responses, usage, phase timings, final cited answer and delivery state.

Use the existing restricted DEV evidence storage/ledger infrastructure. Do not introduce a public source archive, external database or publish full third-party pages to GitHub. Public review packets contain only authorized necessary excerpts/citations, synthetic context and appropriate receipts; private original evidence remains available to authorized review. Tenant-isolated keys and access checks apply even to public source caches; private context must never enter the cross-member public cache. Retention periods and any provider permitted storage scope must be explicit before execution. No content retention permission is assumed here.

## 4. Proposed local resource bounds (design targets, not spending approval)

| Resource | Proposed ceiling / enforcement |
| --- | --- |
| Targets | Two per current brief, unchanged; clarify larger/ambiguous requests |
| Paid search requests | Four total HTTP attempts, one query/request, ten candidate results/request; request permits persisted before transport; no retries/pagination |
| Source retrieval | Eight accepted documents and24 HTTP attempts total, including redirects and robots/access-policy checks; queue cannot recursively expand beyond permits |
| Redirects | At most two/document and counted against24; revalidate every destination |
| HTML/text |256KiB max per document,1MiB aggregate retained bodies; enforce compressed and decoded byte ceilings; oversized documents rejected/coverage disclosed |
| PDF | Design requires locally parsed text PDFs: at most1MiB/document,20 pages, explicit parser CPU/memory/time ceiling; document bodies share aggregate budget. Parser/dependency must pass security review; unavailable/oversized/encrypted/scanned documents explicitly unverified, no paid OCR |
| Extracted model-visible source text |64KiB aggregate, selected deterministically with coverage flags; actual serialized request must also fit current100,000-byte guard. No silent omission of fee exceptions or date applicability; reject incomplete relevant sections or report gaps |
| Network | Search pool25s total; retrieval/parsing pool30s total; bounded per-attempt deadlines within pools, at most two concurrent fetches; no automatic retry |
| Inference | Six attempts maximum per researched turn: input, brief, privacy, extraction, synthesis, final screen. No additional hidden planning, verification or research calls |
| Model output | Keep existing input/final guard4,800; brief/privacy1,400; extraction3,600; synthesis4,800. Explicit reviewed efforts, model IDs and endpoint; no hosted tools on any inference request |
| Whole objective | Proposed360s total research job, not one360s HTTP route. No stage timeout increase; each stage respects its existing25/45/60s ceiling and remaining total deadline |

A single170s turn deadline cannot promise the sum of all stage maxima plus retrieval. Use the existing durable run/ledger as a small **owner-authenticated staged execution record**: one phase per request, each below the existing route ceiling, with compare-and-set phase lease/reservation and terminal state. The existing DEV runner can drive the same phase machine. This does not require a new workflow/queue service or a sleeping serverless request. Do not implement an unprotected continuation endpoint or rely on an open browser to hide retries. Each stage dispatches at most once; an uncertain stage becomes terminal, never resumed/replayed. A known completed stage may advance to the next distinct stage under the same active authorized job, not restart the run. An abandoned job expires without more calls. Global run and per-turn counts/cost limits cover every phase and concurrent worker.

These limits may yield partial findings for large catalogs or complex two-school requests. Resource exhaustion must say exactly which facts remain unverified, not pretend full completion or require the user to discover ordinary source URLs. Unlimited internet coverage is not promised. Retain useful verified findings when safe, without grading partial work as full competency.

## 5. Enforceable spending model

All providers use one durable reservation ledger scoped to the assessment/job, including search and inference, across all phase requests. Parent ledgers are read-only receipts. Prior **$4.25159388**, including **$4.152 unresolved**, remains separate and unchanged. No unused old authorization is carried forward.

Before dispatch, validate an expiring price policy, approved provider/endpoint, exact returned-model allowlist, text-only request, token/output/context limits, search request unit, applicable cache-write/tier/tax/currency surcharges and attempt ceiling. Unknown/unbounded charges mean no dispatch. Reserve atomically, then release only to a validated settled amount. Failed or uncertain transport holds the full maximum and terminates the job; a timeout does not prove the service did no work. No SDK retries. Multiple workers cannot overbook the remaining cap.

For a turn:

`maximum new cost = Σ(6 tool-free inference reservations) + 4 × maximum price per search HTTP attempt + explicitly approved bounded infrastructure charges`

For each inference, conservatively reserve the maximum permitted text-input tokens at the applicable highest input/write rate plus output limit at the applicable output rate. The initial implementation can retain full model-context input reservation rather than guess a token/byte ratio; oversized requests reject before dispatch. No internal multi-step hosted search token multiplier remains. Settlement validates complete status, actual model, token usage and absence of unpriced tools/modalities. Retain existing fail-closed rules.

Any provider requiring an upfront funding purchase must have that cash outlay and account-level auto-reload policy approved separately; prepaid credit does not make calls free. Search availability, rate limits, billing contract, retention permission and real account configuration must be verified before freezing any paid execution manifest. Fixed per-request search is necessary but does not by itself establish semantic research quality.

## 6. New discovery service, documented price and unresolved commercial gate

**No reusable direct general-search integration was found in current source/scripts.** This is not proof no organization account exists; no credentials/accounts were inspected or activated. The existing model-hosted search route is not a substitute under this recommendation.

A concrete price reference is **Brave Search's Search plan**, listed at **$5 per1,000 requests ($0.005/request)**. Four attempts would reserve **$0.02/turn** before any applicable additional charges;1,000 four-search turns would list at$20 search cost, excluding all inference/hosting. Sources checked October21,2026: [official pricing](https://api-dashboard.search.brave.com/documentation/pricing), [official Web Search interface](https://api-dashboard.search.brave.com/documentation/services/web-search), [official account/retention FAQ](https://api-dashboard.search.brave.com/documentation/resources/help-feedback).

**This standard plan is not selected or ready:** the FAQ prohibits retaining API data without separate permission, and account activation requires a payment card. Published monthly credits are conditional and are **not** the design's funding assumption. Written retention terms for auditable candidate provenance are a prerequisite; any changed/custom pricing is unknown and must be bounded before use. The Answers/LLM-context products are not part of this design. No provider call/account verification, signup, card authorization, prepaid purchase or subscription was performed.

Directory discovery tooling was unavailable locally (Stripe CLI absent); its public setup documentation was read only. No installation/provisioning was attempted. The public provider pages above establish a price/rights example, not an account-specific contract or availability confirmation. This architecture does not depend on assuming a provider supplies free requests or unlimited storage rights.

## 7. Implementation scope and acceptance gates

1. Add a server-only direct-search adapter with an explicitly licensed result-retention contract, one-request cost policy and mocked transport; keep provider replaceable at that narrow interface, not introduce an agent platform.
2. Add public retrieval/evidence storage with all redirect/DNS/byte/type/parser limits, identity/source provenance, deterministic quote support and tenant-safe access. Build text-PDF support from a verified existing parser if available; otherwise select/review one maintained local dependency before claiming PDF coverage. No new paid browser/OCR service.
3. Rework only GC discovery/verification into discovery→retrieval→tool-free extraction; retain private stages, synthesis, final checks, ordinary guidance, planning capacity and genuine history. Keep cached identities advisory/revalidated by effective date; source cache never determines competency facts.
4. Extend the existing ledger and owner-authenticated phase control to cover per-request search cost, six text-only inference stages, global deadline and concurrency permits. Persist intent before send, result before delivery, unknown usage as terminal. No new production migration is assumed; any eventual persistence change requires review and separate environment authority.
5. Verify unfamiliar uncataloged schools/credentials/authorities, same-name institutions, malicious/lookalike sites, year correction, directory contradictions, inaccessible/JS/PDF sources, forged quotes, source injection, DNS rebinding/private IPv4/IPv6/mapped addresses, cross-host redirects, decompression bombs, cap-before-dispatch, restart/duplicate workers, missing usage, deadline abandonment and no premature delivery. Prove unknown targets take open discovery without user URLs.
6. Re-run full applicable regression/security/build checks. Only then prepare **one whole-path assessment**, preserving original prompts/criteria and actual follow-up history, with exact source/fixture/manifest hashes and separate authorization. No isolated paid probe cycle. Mocks certify control paths only; an actual delivered answer and independent grading are still necessary.

Tradeoffs: an additional discovery provider and rights/configuration work, modest explicit per-query cost, source-fetch security/parser complexity and a durable phase adapter. In return, unfamiliar-target discovery is preserved, tool charges are locally countable, source facts are auditable and no internal agentic search loop needs inferred billing. Search-index gaps, access restrictions, weak institutional identity evidence, incomplete dates/fees and model interpretation errors remain real limitations, to be reported rather than masked.
